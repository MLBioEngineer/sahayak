# সহায়ক (Sahayak) — ESP32 + AD8232 ECG হার্ডওয়্যার টেলিমেট্রি ও ওয়াইফাই স্থায়ী সমাধান গাইড

এই ডকুমেন্টে ESP32 মাইক্রোকন্ট্রোলারের ঘন ঘন ওয়াইফাই ডিসকানেক্টের মূল কারণ, স্থায়ী উৎপাদন-গ্রেড সমাধান, মোবাইল হটস্পট কনফিগারেশন, সার্কিট ডায়াগ্রাম এবং ফ্ল্যাশিং নির্দেশনা বিস্তারিত দেওয়া হলো।

---

## 🛠️ সমস্যা: কেন ESP32 বারবার ওয়াইফাই থেকে বিচ্ছিন্ন (Disconnect) হয়ে যায়?

ESP32-তে ডিফল্ট Arduino Wi-Fi লাইব্রেরি ব্যবহার করলে ৫টি মারাত্মক সমস্যা দেখা দেয়:

1. **Wi-Fi Modem Sleep (DTIM পাওয়ার সেভিং ড্রপ):**
   - ESP32 ডিফল্টভাবে `WIFI_PS_MIN_MODEM` স্লিপে চলে যায় যাতে বিদ্যুৎ সাশ্রয় হয়।
   - বিশেষ করে **মোবাইল হটস্পট (Android/iOS)** যখন দেখে একটি ডিভাইস স্লিপে আছে বা ট্রাফিক সাময়িক কম, তখন হটস্পট নিজেই ব্যাটারি বাঁচাতে ESP32-কে জোরপূর্বক **Deauthenticate** করে বিচ্ছিন্ন করে দেয়।
2. **মোবাইল হটস্পট চ্যানেল হপিং (Channel Hopping Lockout):**
   - সাধারণ ওয়াইফাই রাউটার একটি নির্দিষ্ট চ্যানেলে থাকে, কিন্তু মোবাইল হটস্পট ডায়নামিকালি চ্যানেল পরিবর্তন করে (যেমন ১ থেকে ৬ বা ১১)। সাধারণ `WiFi.reconnect()` কেবল পুরোনো ক্যাশড চ্যানেলে খুঁজতে থাকে, ফলে হটস্পট চালু থাকলেও আর সংযোগ পায় না।
3. **HTTPS প্রটোকল ত্রুটি ও পোর্ট ৪৪৩ ব্লকেজ:**
   - ক্লাউড সার্ভারগুলো (যেমন Render, Cloudflare) HTTPS চায়। সাধারণ `WiFiClient` পোর্ট ৪৪৩-এ এনক্রিপশন ছাড়া প্লেইনটেক্সট পাঠালে সার্ভার সংযোগ কেটে দেয়।
4. **TCP Keep-Alive রেসপন্স বাফার ডি-সিঙ্ক (Socket Exhaustion):**
   - `http.setReuse(true)` ব্যবহার করার পর পূর্ববর্তী HTTP POST-এর সার্ভার রেসপন্স ড্রেন (`http.getString()`) না করলে পরবর্তী প্যাকেট পাঠাতে গিয়ে lwIP সকেট টেবিল ক্র্যাশ করে।
5. **ব্লকিং রিকানেকশন ও ফ্রিজ (Watchdog Reset):**
   - সাধারণ কোডে `while (WiFi.status() != WL_CONNECTED) delay(500);` থাকে। ওয়াইফাই সাময়িক ড্রপ করলে পুরো ESP32 ফ্রিজ হয়ে যায়, এডিসি স্যাম্পলিং বন্ধ হয় এবং FreeRTOS Task Watchdog ট্রিগার হয়ে ডিভাইস রিবুট মারে।
6. **ADC2 ও ওয়াইফাই কনফ্লিক্ট:**
   - ESP32-এর ADC2 পিনগুলো (GPIO 0, 2, 4, 12-15, 25-27) ওয়াইফাই চলাকালীন কাজ করে না। ADC1 পিন (যেমন GPIO 34) ব্যবহার না করলে রিডিং এলোমেলো হয়ে যায়।

## 🚀 স্থায়ী সমাধান (Permanent Stabilized Fix)

আমাদের ফার্মওয়্যারে নিম্নলিখিত ক্লিনিক্যাল-গ্রেড সুরক্ষা বাস্তবায়ন করা হয়েছে:

1. **মডেম স্লিপ সম্পূর্ণ নিষ্ক্রিয় ও স্থায়ী রিবাইন্ডিং (`applyWiFiPowerAndSleepFix()`):**
   - `WiFi.setSleep(false)` এবং `esp_wifi_set_ps(WIFI_PS_NONE)` সেটআপে এবং প্রতিটি `ARDUINO_EVENT_WIFI_STA_CONNECTED` ও `GOT_IP` ইভেন্টে পুনঃপ্রয়োগ করা হয়। মোবাইল হটস্পট কখনোই ডিভাইসটিকে আইডল মনে করে বিচ্ছিন্ন করে না।
2. **৩-স্তরের এস্কেলেশন নন-ব্লকিং রিকানেকশন (3-Stage Hotspot Recovery):**
   - **স্টেজ ১ (<১২ সেকেন্ড):** সাময়িক আরএফ ড্রপের জন্য দ্রুত `WiFi.reconnect()` চালানো হয়।
   - **স্টেজ ২ (১২-৪৫ সেকেন্ড):** মোবাইল হটস্পটের চ্যানেল পরিবর্তন হ্যান্ডেল করতে সম্পূর্ণ ২.৪ GHz চ্যানেল স্ক্যানসহ `WiFi.disconnect(); WiFi.begin(...)` করা হয়।
   - **স্টেজ ৩ (>৪৫ সেকেন্ড):** দীর্ঘমেয়াদী বিভ্রাটের ক্ষেত্রে পুরো ওয়াইফাই রেডিও সাবসিস্টেম রিসেট (`WiFi.mode(WIFI_OFF)` $\to$ `WiFi.mode(WIFI_STA)`) করা হয়।
3. **ডুয়াল প্রটোকল সাপোর্ট (`WiFiClientSecure` + `WiFiClient`):**
   - ক্লাউড রেন্ডার সার্ভারের জন্য স্বয়ংক্রিয়ভাবে টিএলএস (`clientSecure.setInsecure()`) সক্রিয় হয়।
   - লোকাল নেটওয়ার্ক আইপির জন্য লাইটওয়েট প্লেইন এইচটিটিপি ব্যবহার করা হয়।
4. **সকেট লিক প্রতিরোধ ও Keep-Alive ড্রেনিং:**
   - প্রতিবার সফল POST-এর পর `http.getString()` কল করে টিসিপি বাফার সম্পূর্ণ পরিষ্কার করা হয়, যাতে পরবর্তী প্যাকেটে সকেট পুনরায় ব্যবহার নিশ্চিত হয়। এরর হলে `http.end()` এবং `client.stop()` সকেট অবমুক্ত করে।
5. **FreeRTOS ডুয়াল-কোর বিচ্ছিন্ন আর্কিটেকচার:**
   - **Core 1 (Priority 5 - High):** প্রতি ১০ মিলিসেকেন্ডে (১০০ হার্জ) AD8232 থেকে নির্ভুল ইসিজি ডেটা কিউতে (`ecgQueue`) জমা করে। ওয়াইফাই বন্ধ থাকলেও Core 1 এক মিলি-সেকেন্ডের জন্যও থামে না।
   - **Core 0 (Priority 1):** ওয়াইফাই ও এইচটিটিপি ক্লায়েন্ট পরিচালনা করে। সংযোগ ড্রপ হলে নন-ব্লকিং পদ্ধতিতে রিকানেক্ট করে।
6. **ফ্লোটিং পিন সুরক্ষা (Electrostatic Protection):**
   - AD8232-এর LO+ এবং LO- পিনে ইন্টারনাল `INPUT_PULLDOWN` ব্যবহার করা হয়েছে, যাতে ব্যবহারকারী কেবল ৩টি তার লাগালেও রিডিং শূন্যে আটকে না থাকে।
7. **ডায়নামিক বাফার ড্রেনিং (Queue Backlog Clearance):**
   - ওয়াইফাই ড্রপের পর সংযোগ ফিরলে কিউতে জমে থাকা স্যাম্পল দ্রুত ক্লিয়ার করতে ডায়নামিকালি বড় ব্যাচ (৮০ স্যাম্পল পর্যন্ত) পাঠানো হয়।

## 💻 কীভাবে ফার্মওয়্যার ফ্ল্যাশ করবেন (Flashing Guide)

### পদ্ধতি ১: Arduino IDE (সবচেয়ে সহজ)

1. Arduino IDE ওপেন করুন (v2.x বা v1.8.x)।
2. **Tools > Board > esp32 > ESP32 Dev Module** নির্বাচন করুন।
3. সেটিংস মিলিয়ে নিন:
   - **Upload Speed:** `921600` (অথবা সমস্যা হলে `115200`)
   - **CPU Frequency:** `240MHz (WiFi/BT)`
   - **Flash Frequency:** `80MHz`
   - **Flash Mode:** `QIO`
   - **Port:** আপনার ডিভাইসের COM পোর্ট (যেমন `COM3`, `COM4`)
4. এই ফাইলটি ওপেন করুন:
   `D:\sahayak AI\hardware\esp32_streamer\esp32_streamer.ino`
5. **Upload (➡️)** বাটনে চাপ দিন।
6. আপলোড শেষ হলে **Serial Monitor (115200 baud)** ওপেন করুন।

### পদ্ধতি ২: PlatformIO (VS Code)

1. VS Code-এ `D:\sahayak AI\esp32` ফোল্ডারটি ওপেন করুন।
2. নীচের স্ট্যাটাস বার থেকে **PlatformIO: Upload** বাটনে ক্লিক করুন অথবা টার্মিনালে চালান:
   ```bash
   pio run -t upload
   ```
3. সিরিয়াল মনিটর দেখতে:
   ```bash
   pio device monitor -b 115200
   ```
